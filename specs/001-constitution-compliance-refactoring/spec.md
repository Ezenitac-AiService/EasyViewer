- Q: `FR-012`와 `SC-006`의 런타임 성능 무회귀 검증에서 테마 전환 같은 짧은 작업의 일시적 지연 변동(Jitter)으로 인한 거짓 실패를 막기 위해 어떤 판정 기준을 적용해야 합니까? → A: 중앙값 + 복합 임계치(Option B) — 워밍업 실행을 제외한 다회 반복 중앙값($p_{50}$)을 기준으로, 기준선 대비 +10%를 초과하면서 동시에 +15ms 이상 느려진 경우에만 성능 회귀로 판정한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기존 핵심 동작 보존을 위한 자동화 검증 안전망 구축 (Priority: P1)

유지보수자와 개발자는 기존 도서 뷰어 기능을 리팩토링하기 전에 현재 동작을 자동으로 검증하는 특성화 테스트(Characterization Test)와 경계 격리 검증 기반을 구축한다. 이를 통해 구조 변경 중에도 문서 처리, 독서 위치 보존, 동기화 병합, 설정 관리가 손상되지 않음을 즉시 확인할 수 있고, 이후 모든 개발 작업이 테스트 주도 주기로 진행될 수 있다.

**Why this priority**: 자동화된 검증 스위트 없이 리팩토링을 수행하면 기존 동작 회귀 위험이 크며, 테스트 없는 구현 금지라는 프로젝트 최우선 규범을 충족할 수 없기 때문이다.

**Independent Test**: 리팩토링 대상 구조를 변경하기 전에 1계층 경량 단위·경계 테스트와 2계층 실제 브라우저 렌더링 테스트로 분리된 검증 절차를 실행해 핵심 도메인 로직, 경계 계약, 레이아웃 기반 동작의 결정적인 통과/실패 결과를 확인함으로써 독립 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 1계층 자동화 검증 안전망이 구축된 저장소에서, **When** 유지보수자가 경량 단위·경계 테스트를 실행하면, **Then** 순수 문서 파싱·검색, 독서 위치 오프셋/진행률 계산, 동기화 충돌 병합, 설정 상태 및 플랫폼 경계 계약이 외부 네트워크나 실제 운영체제 창 없이 결정적으로 수행되고 결과를 보고한다.
2. **Given** 실제 화면 측정과 프레임 격리가 필요한 보기 모드(세로 스크롤 ↔ 가로 페이지 넘김) 전환, 테마·글꼴 변경, 전자책 탭/CSP 시나리오에서, **When** 2계층 실제 브라우저 렌더링 검증을 실행하면, **Then** 전환 전후의 독서 위치 보존, 페이지 분할 정합성, 전자책 내 스크립트 차단 및 탭 상호작용이 실제 렌더링 엔진에서 자동으로 검증된다.
3. **Given** 운영체제 저장소·파일 대화상자·원격 서버와의 연동이 필요한 기능에 대해, **When** 격리된 테스트 대역 환경에서 오류 및 경계 조건을 실행하면, **Then** 실제 사용자 파일이나 원격 데이터를 변경하지 않고도 정상 경로와 예외 처리 동작을 검증할 수 있다.

### User Story 2 - 플랫폼 종속 호출의 단일 추상화 경계 통합 (Priority: P2)

유지보수자는 서재 화면과 상태 관리 영역에 흩어져 있는 운영체제·실행 환경 직접 호출(파일/폴더 선택 대화상자, 삭제 확인 대화상자, 드래그앤드롭 경로 처리, 저장 경로 해석)을 통합 플랫폼 추상화 계층으로 이전한다. 사용자는 데스크톱, 모바일, 웹 브라우저 어느 환경에서든 일관된 흐름으로 도서를 추가·관리·열람할 수 있으며, 데스크톱 전용 저장 폴더 관리 등 환경 고유 기능은 지원 여부에 따라 안전하게 구분·안내된다.

**Why this priority**: 상위 화면 및 상태 계층이 특정 실행 환경의 기능을 직접 호출하면 크로스 플랫폼 일관성이 깨지고, 격리 테스트와 유지보수가 어려워지기 때문이다.

**Independent Test**: 상위 화면 및 상태 계층을 플랫폼 추상화 계층에만 의존하도록 전환한 뒤, 데스크톱·웹·모바일 시나리오별 모의 경계에서 파일 가져오기, 저장 폴더 변경, 도서 삭제 확인, 드래그앤드롭 동작이 기존과 동일하게 수행됨을 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 데스크톱 또는 웹 브라우저에서 도서 파일을 화면에 드래그앤드롭하거나 파일 선택으로 추가할 때, **When** 상위 화면이 통합 플랫폼 추상화 계층의 입력 처리 기능을 호출하면, **Then** 실행 환경에 맞는 파일 읽기 및 저장 방식이 내부에서 선택되어 도서가 서재에 추가된다.
2. **Given** 사용자가 데스크톱에서 저장 폴더를 변경·열기하거나 로컬 파일 포함 도서 삭제를 요청할 때, **When** 상위 계층이 추상화된 대화상자 및 폴더 관리 계약을 호출하면, **Then** 사용자 확인과 폴더 접근 권한 갱신이 일관되게 처리되며, 폴더 변경을 지원하지 않는 환경에서도 오류 없이 안전한 안내 또는 폴백 동작을 제공한다.
3. **Given** 리팩토링이 완료된 코드베이스에서, **When** 통합 플랫폼 추상화 계층 외부의 상위 화면·상태 관리 모듈을 점검하면, **Then** `FR-004`에 정의된 플랫폼 분기 기능의 네이티브/환경 전용 API를 직접 호출하는 코드 경로가 존재하지 않는다.

### User Story 3 - 포괄 보안 정책 및 네트워크·콘텐츠 격리 강화 (Priority: P3)

사용자와 유지보수자는 애플리케이션의 콘텐츠 보안 정책(CSP) 비활성화 상태를 해소하고, 전자책 내장 콘텐츠의 스크립트 실행 격리, 파일 시스템 최소 권한 스코프, 원격 중계(프록시)의 내부망 접근(SSRF) 차단, TLS 인증서 검증 및 원격 자격증명 보호 기준을 정비한다. 이를 통해 로컬 전자책·텍스트 열람, 원격 도서 다운로드, 동기화 기능을 유지하면서도 XSS, 비인가 파일 접근, 내부망 우회 요청 및 자격증명 노출 위험을 차단한다.

**Why this priority**: 보안 정책이 비활성화된 상태에서는 악성 스크립트가 포함된 전자책이나 신뢰할 수 없는 원격 네트워크 경로를 통해 치명적인 보안 취약점에 노출될 수 있으므로, 정식 배포 전 앱·콘텐츠·네트워크 3중 보안 경계를 확립해야 하기 때문이다.

**Independent Test**: 강화된 콘텐츠 보안 정책, 전자책 콘텐츠 격리, 파일 권한 스코프, 원격 프록시 SSRF/TLS 검증을 적용한 상태에서 로컬 도서 열람, 테마·글꼴 적용, 유효한 원격 다운로드 및 동기화가 정상 작동하고, 비인가 스크립트·사설망 주소·미승인 비신뢰 인증서 요청이 차단됨을 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 명시적 콘텐츠 보안 정책과 전자책 콘텐츠 격리가 활성화된 상태에서, **When** 사용자가 전자책 및 텍스트 도서를 열고 라이트·다크·세피아 테마와 글꼴을 변경하거나 본문을 탭/선택하면, **Then** 앱의 정상적인 읽기 상호작용과 스타일 렌더링은 손상 없이 동작하고 도서 내부에 삽입된 스크립트·이벤트 핸들러·위험 URI는 실행되지 않는다.
2. **Given** 사용자가 허용된 외부 원격 주소에서 도서를 내려받거나 독서 위치를 동기화할 때, **When** 네트워크 요청과 로컬 저장이 수행되면, **Then** 승인된 프로토콜과 지정 저장 폴더 범위 내에서만 동작이 허용되고 비인가 파일 경로 및 고위험 내부망(루프백·클라우드 메타데이터·리다이렉트를 통한 내부 전환·타 출처 프록시 남용) 대상 요청은 거부된다.
3. **Given** 사설 IP 대역의 개인 NAS 또는 자체 서명 인증서를 사용하는 서버에 연결할 때, **When** 사용자가 직접 입력한 연결에 대해 명시적 확인·동의를 수행하지 않으면, **Then** 기본적으로 차단되며, 사용자가 명시적으로 확인·승인한 연결에 한해서만 동일 출처가 검증된 경로를 통해 예외 접속을 허용한다.

### User Story 4 - 구현 무결성 점검 및 품질·거버넌스 게이트 정착 (Priority: P4)

유지보수자는 전체 코드베이스에서 임시 우회 로직, 미완성 스텁, 정적 분석 경고, 배포 대상 간 버전 불일치를 점검·정리하고, 프론트엔드·네이티브 백엔드·테스트·플랫폼 경계 위반 탐지·버전 일관성·커밋 메시지 형식 검증을 자동화한 품질 게이트와 리서치·무결성 검토 체크리스트를 확립한다.

**Why this priority**: 단발성 리팩토링으로 끝나지 않고 이후 모든 기능 개발에서도 헌법의 품질·아키텍처·언어 규범이 재현 가능하게 검증되도록 지속 가능한 게이트를 고정해야 하기 때문이다.

**Independent Test**: 전체 빌드, 타입 검사, 프론트엔드 및 네이티브 백엔드 검증, 자동화 테스트, 플랫폼 경계 우회 호출 탐지, 버전 일치 점검, 커밋 메시지 형식 검증 스크립트를 실행해 정상 케이스는 통과하고 규범 위반 케이스는 탐지·실패 처리됨을 확인하여 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 리팩토링이 완료된 프로젝트에서, **When** 유지보수자가 통합 품질 검증 절차를 실행하면, **Then** 프론트엔드 빌드, 정적 타입 검사, 1·2계층 자동화 테스트 스위트, 네이티브 백엔드 검사 및 테스트, 플랫폼 경계 우회 호출 탐지, 배포 대상 간 버전 동기화 검증이 모두 오류 없이 통과한다.
2. **Given** 커밋 메시지 형식 및 변경 점검 도구가 구성된 상태에서, **When** 커밋 메시지 규범(타입 접두사 및 한국어 상세 본문) 또는 플랫폼 경계 규범 위반 사례를 검증기에 입력하면, **Then** 위반 사유가 명확히 출력되고 검증 실패로 판정된다.
3. **Given** 프로덕션 코드 전반을 대상으로 무결성 점검을 수행할 때, **When** 하드코딩된 테스트 우회 분기나 미구현 모의 로직 잔존 여부를 검토하면, **Then** 실제 런타임 동작을 대체하는 우회·모의 코드가 발견되지 않으며 리서치 근거 및 무결성 검토 체크리스트가 확인된다.

---

### Edge Cases

- 사용자가 지원하지 않는 파일 형식, 허용 상한을 초과한 비정상 대용량/압축 폭탄(Zip Bomb) 아카이브, 또는 손상된 도서 파일을 드래그앤드롭·파일 선택기·원격 다운로드로 추가하려 할 때, 파싱/압축 해제 전 상한 검증으로 자원 고갈 없이 즉시 거부하고 기존 서재 데이터가 손상되지 않으며 명확한 오류 안내를 제공해야 한다.
- 사용자가 파일/폴더 선택 대화상자 또는 삭제 확인 대화상자를 취소했을 때, 상태 변경이나 파일 삭제 없이 안전하게 중단되어야 한다.
- 데스크톱에서 이전에 지정했던 외부 저장 폴더가 삭제되었거나 접근 권한이 해제된 상태에서 앱을 재시작할 때, 앱이 비정상 종료되지 않고 사용자에게 안내하며 복구 가능한 상태를 유지해야 한다.
- 강화된 콘텐츠 보안 정책 하에서 내부 스타일시트나 인라인 이미지를 포함한 전자책 문서를 열람할 때, 정상 문서 콘텐츠와 사용자 탭·선택 상호작용은 유지되면서 외부·내부 악성 스크립트 및 샌드박스 우회 경로는 차단되어야 한다.
- 원격 다운로드 또는 동기화 중 중계(프록시) 경로나 HTTP 리다이렉트를 통해 루프백·클라우드 메타데이터 등 고위험 내부 주소로 접근하거나, 우회 IP 표기(IPv6 매핑 등) 및 타 출처(Cross-Origin) 요청으로 프록시를 악용하려 할 때, 즉시 차단하고 명확한 보안 오류를 반환해야 한다.
- 사용자가 사설 IP 대역의 개인 NAS 또는 자체 서명 TLS 인증서 서버에 연결하려 할 때, 사용자의 명시적 확인·동의 없이는 자동 우회 접속해서는 안 된다.
- 기존 버전에 평문으로 저장된 원격 저장소 비밀번호 기록이 로드될 때, 연결 프로필(주소·사용자명·초기 경로)을 유실하지 않으면서 평문 비밀번호를 안전 저장소로 이관하거나 정책에 맞게 정리해야 한다.
- 웹 브라우저나 모바일처럼 데스크톱 전용 저장 폴더 기능이 제공되지 않는 환경에서 플랫폼 추상화 계층의 폴더 관련 기능을 호출할 때, 예외 미처리 크래시 없이 환경에 맞는 안전 반환값 또는 안내를 제공해야 한다.
- 원격 다운로드 또는 동기화 도중 네트워크 연결이 끊기거나 인증에 실패할 때, 불완전한 도서 항목이나 손상된 독서 위치가 저장소에 기록되지 않아야 한다. 단, 원격 동기화에서 일시적 네트워크 단절(오프라인) 시에는 로컬 허브 동기화로 안전하게 폴백하되, SSRF 차단·사설망 NAS 승인 필요·자체 서명 TLS 검증 실패 등 보안 예외는 절대 폴백으로 은폐하지 않고 사용자에게 즉시 차단 오류 또는 명시적 동의 확인을 제공해야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 프로젝트는 **2계층 자동화 검증 체계**를 제공해야 한다(MUST). 1계층은 외부 네트워크나 실제 브라우저 창 없이 순수 도메인 로직(텍스트 청킹·검색·인코딩 감지, 위치 오프셋 계산, 동기화 병합, 설정·서재 상태, 플랫폼 추상화 어댑터)을 검증하고, 2계층은 실제 브라우저 렌더링 환경에서 화면 측정 기반 페이지네이션, 보기 모드 전환 시 위치 보존, 전자책 콘텐츠 격리(CSP)·상호작용을 검증한다.
- **FR-002**: 1계층 자동화 테스트 스위트는 플랫폼 및 런타임 경계(네이티브 백엔드 브리지, 파일 시스템, 네트워크, 브라우저 로컬 저장소)를 안전하게 격리하는 테스트 대역 메커니즘을 포함해야 하며(MUST), 해당 대역은 테스트 환경 내부에서만 사용되어야 한다(MUST). 반면 실제 레이아웃·렌더링 정합성은 2계층 실제 브라우저 렌더링 테스트로 검증해야 한다(MUST).
- **FR-003**: 기존 핵심 사용자 기능(로컬 도서 가져오기, 도서 열람, 보기 모드 및 테마·글꼴 전환, 책갈피·검색, 원격 다운로드, 동기화 병합)의 현재 동작을 고정하는 특성화 테스트가 1·2계층에 걸쳐 구조 변경에 앞서 작성되고 통과해야 한다(MUST).
- **FR-004**: 통합 플랫폼 추상화 계층은 실행 환경(데스크톱, 모바일, 웹)에 따라 구현이 분기되는 플랫폼 기능—파일 읽기/쓰기, 영속 저장, 네트워크 통신, 사용자 파일/폴더 선택 대화상자, 확인 대화상자, 경로 해석, 파일 드래그앤드롭 입력 처리—을 단일 계약으로 캡슐화하여 제공해야 하며(MUST), 데스크톱 전용 저장 폴더 기능과 모바일·웹 내부 저장소의 의도된 기능 차이를 안전하게 구분·안내해야 한다(MUST).
- **FR-005**: 리팩토링 완료 후 모든 상위 화면 및 상태 관리 계층은 `FR-004`에 정의된 플랫폼 분기 기능을 통합 플랫폼 추상화 계층을 통해서만 호출해야 하며(MUST), 추상화 계층 외부에서 네이티브 플랫폼 API나 환경 분기 저장/파일 API를 직접 호출해서는 안 된다(MUST NOT). 단, 모든 웹뷰/브라우저 환경에 공통으로 적용되는 표준 UI 화면 제어(키보드·리사이즈 이벤트, 텍스트 선택, 테마 클래스 적용)는 본 금지 대상에서 제외한다.
- **FR-006**: 문서 렌더링 엔진(텍스트 및 전자책)은 공통 도메인 데이터 계약만을 통해 상위 화면 및 상태 관리 계층과 분리된 상태를 유지해야 하며(MUST), 보기 모드 및 테마·글꼴 변경 시 독서 위치가 보존되어야 한다(MUST).
- **FR-007**: 애플리케이션의 보안 설정은 비활성화(무제한 허용) 상태를 제거하고, 외부 폰트 CDN 등 불필요한 외부 웹 자산 의존성을 제거해 로컬 번들 자산·OS 기본 글꼴·전자책 렌더링·허용된 원격 통신과 호환되면서 비인가 스크립트 및 외부 리소스 로드를 차단하는 명시적 콘텐츠 보안 정책(CSP)을 적용해야 하며(MUST), 전자책 내장 콘텐츠는 읽기 상호작용(탭·선택·내부 링크)을 유지한 채 임의 스크립트 실행과 상위 앱 컨텍스트 탈출이 불가능하도록 다중 격리(콘텐츠 정화 및 샌드박스 정책)를 보장하고(MUST), 도서·아카이브(EPUB 등) 파싱 전 파일 크기·엔트리 수·압축 해제 총량 상한을 검증해 자원 고갈(Zip Bomb 등)을 차단해야 한다(MUST).
- **FR-008**: 데스크톱의 사용자 지정 저장 폴더 접근 권한과 모바일·웹의 내부 저장소 접근 권한은 각 실행 환경의 최소 필요 범위로 제한되어야 하며(MUST), 심볼릭 링크 탈출·시스템 민감 경로·미승인 임의 경로에 대한 접근·등록 요청은 백엔드 신뢰 경계에서 거부되어야 한다(MUST).
- **FR-009**: 원격 도서 다운로드 및 WebDAV 동기화 경계(원격 중계 프록시 포함)는 신뢰할 수 없는 클라이언트 검사에만 의존하지 않고 실제 네트워크 요청을 수행하는 신뢰 계층에서 URL 정규화, DNS 해석 결과 사설 IP 확인·연결 고정, 루프백·클라우드 메타데이터/링크로컬 주소·우회 인코딩 표기(IPv4 매핑 IPv6 등)·HTTP 리다이렉트를 통한 내부망 전환을 우회 불가능하게 차단하며(MUST), 응답 크기·요청 크기·타임아웃·허용 HTTP 메서드 상한과 WebDAV 경로 탐색(`..` 등) 차단을 강제해야 한다(MUST). 원격 중계 경로는 동일 출처(`Origin`/`Sec-Fetch-Site`) 및 실행 단위 검증을 실패 시 차단(Fail-Closed) 원칙으로 적용해 외부 사이트의 프록시 악용을 막아야 한다(MUST). 사설 IP 대역(`.local` 포함)의 개인 NAS 및 자체 서명 TLS 인증서는 기본적으로 차단하되 사용자가 직접 입력하고 명시적으로 동의한 연결에 한해 예외 허용한다(MUST). 원격 접속 비밀번호는 기본적으로 현재 실행 세션 동안만 메모리에 보관하며, 사용자가 명시적으로 "비밀번호 기억"을 선택한 경우 네이티브 환경에서는 플랫폼 안전 저장소로 분리 보관하고 웹 환경에서는 브라우저 로컬 저장 한계 안내 후 선택을 허용해야 한다(MUST).

- **FR-011**: 프로젝트는 프론트엔드 빌드, 정적 타입 검사, 프론트엔드·백엔드 자동화 테스트, 플랫폼 추상화 경계 우회 호출 탐지, 배포 대상 간 버전 일치 검증 및 커밋 메시지 형식(타입 접두사 및 한국어 상세 본문) 검증을 자동화된 검사 수단으로 제공해야 하며(MUST), 프로덕션 코드 내에 하드코딩 우회 로직이나 미완성 목업이 남아 있지 않아야 하고(MUST NOT), 검토·설계 산출물의 리서치 근거 및 무결성 검토 체크리스트를 정착시켜야 한다(MUST).
- **FR-012**: 리팩토링 전후의 핵심 런타임 구간(서재 초기화, 대용량 텍스트 문서 열람·청킹, 보기 모드 및 테마 전환 — 웹 브라우저 DOM·레이아웃 기준선 및 데스크톱 서재 초기화 경계 호출 상한 포함)에 대해 리팩토링 착수 전 워밍업을 제외한 다회 반복 측정 기준선(중앙값) 지표를 기록하고, 리팩토링 완료 후 동일 조건에서 통계적으로 유의미한 성능 회귀가 발생하지 않음을 검증해야 한다(MUST).

### Key Entities

- **도서(Book)**: 사용자가 서재에 등록한 문서 단위. 고유 식별자, 제목, 저자, 포맷 구분(텍스트/전자책), 파일 크기, 저장 위치 정보, 오프라인 캐시 여부, 마지막 독서 위치를 포함한다.
- **독서 위치(Reading Position)**: 특정 도서에서 사용자가 읽고 있는 정확한 지점. 도서 식별자, 위치 로케이터, 진행 백분율, 챕터 정보, 갱신 시각, 기기 식별자를 포함하며 보기 모드·테마 전환 및 동기화 시 보존 기준이 된다.
- **플랫폼 추상화 경계(Platform Capability Boundary)**: 실행 환경(데스크톱, 모바일, 웹)에 따라 달라지는 파일 저장소, 폴더 관리, 사용자 대화상자, 경로 처리, 드래그앤드롭, 네트워크 요청을 단일 인터페이스로 제공하는 경계 계약.
- **보안 정책 프로필(Security Policy Profile)**: 애플리케이션이 허용하는 스크립트·스타일·이미지·폰트·네트워크 출처, 전자책 콘텐츠 격리 규칙, 원격 중계 SSRF/TLS 검증 규칙, 자격증명 보호 및 파일 시스템 접근 스코프를 정의하는 보안 규칙 집합.
- **검증 스위트(Verification Suite)**: 순수 로직·어댑터 계약 검증(1계층), 실제 브라우저 레이아웃·CSP·상호작용 검증(2계층), 네이티브 백엔드 테스트, 정적 타입·빌드·버전 동기화 점검을 포함하는 다층 자동화 검증 체계.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 1계층 프론트엔드 단위·경계 테스트 실행 시 외부 네트워크 연결 없이 30초 이내에 100% 결정적으로 통과하며, 2계층 실제 브라우저 렌더링 검증과 네이티브 백엔드 테스트까지 포함한 전체 검증 스위트 역시 오류 없이 100% 통과한다.
- **SC-002**: 상위 UI 화면 및 상태 관리 계층에서 통합 플랫폼 추상화 계층을 우회해 `FR-004`에 정의된 플랫폼 분기 기능의 네이티브/환경 전용 API를 직접 호출하는 코드 경로가 0건이 된다.
- **SC-003**: 기존 사용자 시나리오(도서 추가·드래그앤드롭, 도서 열람, 보기 모드·라이트/다크/세피아 테마·글꼴 전환, 책갈피·검색, 원격 다운로드, 동기화)에서 리팩토링으로 인한 회귀 결함이 0건이다.
- **SC-004**: 외부 폰트 CDN 의존성이 제거된 명시적 콘텐츠 보안 정책(CSP), 전자책 격리, 원격 중계 SSRF/동일 출처/TLS 검증 및 파일 권한 스코프 적용 상태에서 허용된 로컬·원격 및 사용자 승인 사설망 NAS 기능이 100% 정상 동작하며, 전자책 내 삽입 스크립트·고위험 내부망(루프백·메타데이터·우회 표기·리다이렉트) SSRF 요청·타 출처 프록시 요청·미승인 비신뢰 인증서·비인가 외부 리소스 로딩 테스트 케이스가 100% 차단된다.
- **SC-005**: 프론트엔드 빌드, 정적 타입 검사, 프론트엔드·네이티브 백엔드 테스트, 플랫폼 경계 탐지, 모든 배포 대상의 버전 일치 검증 통과율 100%를 달성하며, 의도적으로 주입한 규범 위반(형식 위반 커밋 메시지, 플랫폼 경계 우회 호출)에 대해 자동 검사 수단의 탐지율 100%를 기록한다.
- **SC-006**: 워밍업 실행을 제외한 다회 반복 측정의 중앙값 기준으로, 리팩토링 전 기준선 대비 서재 초기화, 대용량 텍스트(1MB 이상) 열람, 보기 모드·테마 전환의 핵심 구간 중 `+10%` 초과와 `+15ms` 이상 지연을 동시에 초과하는 회귀 구간이 0건이다.

## Assumptions

- 본 리팩토링은 기존에 구현된 기능의 외부 동작과 사용자 데이터 형식을 그대로 유지하면서 구조적 정합성, 테스트 가능성, 보안 정책을 프로젝트 헌법 수준으로 끌어올리는 데 집중한다. 단, 보안 경계 강화(`FR-009`)에 따른 자체 서명 인증서·사설망 NAS 연결·자격증명 저장 확인 안내 및 비정상 대용량/압축 아카이브 차단 오류 안내(`FR-007`)는 허용된 범위 내 예외로 포함한다.
- 신규 도서 포맷 지원이나 신규 사용자 기능 추가(예: 새로운 동기화 프로토콜, UI 전면 개편, 문서 렌더링 엔진 전면 교체 등)는 본 리팩토링 범위에서 제외한다. 단, 현행 전자책 렌더링 엔진의 유지보수·보안 부채는 후속 개선 과제로 분리 추적한다.
- 자동화된 로컬/CI 환경에서 직접 실행할 수 없는 모바일 실기기(Android/iOS) UI 상호작용과 macOS 배포 서명/샌드박스 권한 동작은 플랫폼 추상화 경계 계약 테스트, 네이티브 빌드 검증, 데스크톱/웹 검증으로 1차 검증한 뒤 실기기·실앱 확인 절차를 따른다.
- 원격 도서 다운로드 및 WebDAV 동기화 기능은 사용자가 입력하는 외부 원격 호스트 주소를 지원해야 하므로, 앱 내부 스크립트 보호와 사용자 지정 원격 요청 허용 간의 균형을 유지하되 내부망 대상 SSRF 차단과 자체 서명 인증서에 대한 명시적 사용자 동의 원칙을 전제로 한다.
