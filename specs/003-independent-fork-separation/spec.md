## 분리 목적과 표현 원칙 (최우선)

이 명세는 EasyViewer 저장소를 업스트림(`edith2580/EasyViewer`)에서 독립된 포크 프로젝트(`Ezenitac-AiService/EasyViewer`)로 분리한다. 범위는 다섯 가지다: **법적 준수**, **저장소 독립**, **지원 플랫폼 범위 전환**, **앱 정체성 분리**, **기존 사용자 데이터 보호**. 뷰어 기능 추가나 재작성은 범위가 아니다. 형제 프로젝트 ImageViewer의 `003-independent-fork-separation`을 선례로 삼되, EasyViewer는 원저작자가 같은 이름의 멀티플랫폼 앱을 계속 배포하고 있다는 점이 다르다.

- 이 포크의 **지원 범위는 macOS · iOS · Linux**이다. 설계·검증·품질 투자는 이 세 플랫폼을 기준으로 한다.
- **Windows는 이 포크의 공식 지원·배포 대상이 아니며, Windows 사용자에게는 원저작자(`edith2580/EasyViewer`)의 애플리케이션 사용을 권장한다.**
- 공개 문구는 **포크 자신의 범위만** 말한다. 원저작자 프로젝트의 역할·의도·지원 범위를 대신 규정하지 않는다.
  - "역할 분담", "경쟁하지 않는다" 같은 표현은 원저작자가 동의한 경우에만 쓴다.
  - 원저작자 앱도 macOS·Linux·Android를 배포하는 멀티플랫폼 앱이라는 사실을 왜곡하지 않는다.
- 이 원칙은 아래 모든 요구사항보다 우선한다.

## 배경

- 포크는 업스트림 `v0.1.6`(`44c4d37`)에서 갈라진 뒤 독자 리팩토링(002)으로 7커밋 앞서 있다.
- 업스트림은 2026-11-17에 `v0.2.0`(`eaf6471`)과 `v0.2.1`(`40c4605`)을 릴리스했다. 분기 이후의 업스트림 변경은 병합하지 않는다.
- 포크의 001 리팩토링은 업스트림에 기여(PR #2)되어 병합된 적이 있다. 앞으로 포크는 업스트림을 병합하지 않는다. 업스트림 아이디어가 필요하면 별도 명세로 재구현한다.
- 포크 상태에서는 PR 기본 대상이 업스트림이고 저장소 코드 검색이 제한된다.
- 앱 식별자(`com.edith.easyviewer`)·제품명·설치 파일명이 원저작자 앱과 같다. 그래서 같은 기기에서 서로 덮어쓰거나 설치가 실패하고 데이터가 섞인다.
- 포크는 앱 내부 데이터 형식을 원저작자보다 새 버전으로 올렸다. 원저작자 앱은 포크가 만든 데이터를 열 수 없다.
- 라이선스 전문은 있지만 저작권·출처 고지, 변경 고지, 패키지 라이선스 선언, 의존성 라이선스 자동 감사가 없다.
- 포크는 지금까지 Windows 설치 파일을 프리릴리스로 게시해 왔다.

## 확정된 결정

1. **저장소**: 기존 `Ezenitac-AiService/EasyViewer`를 유지하고(URL·스타·이슈·릴리스 이력 보존) GitHub Support에 포크 네트워크 분리를 요청한다. 로컬·CI의 업스트림 동기화 경로는 모두 제거한다.
2. **앱 식별자**: 모든 플랫폼에서 `com.ezenitac.easyviewer`로 바꾼다.
3. **분기 기준선**: `44c4d37`에 불변 주석 태그 `upstream-base-v0.1.6`을 만든다.
   - 기존 lightweight 태그 `v0.1.6`과 같은 커밋이지만, 의미와 불변성을 명시하려고 별도로 둔다.
   - 분기 이후 업스트림 릴리스(작성 시점 `v0.2.0`·`v0.2.1`) 미병합 사실을 기록한다.
4. **라이선스 선언**: `GPL-3.0-only`. 이는 포크의 **선택**이다. 원저작자가 "이후 버전" 허용 의사를 밝히면 재검토한다.
5. **앱 내 정보 화면**: 둔다. 법적 의무가 아니라 **자발적 투명성 정책**이다(원 프로그램에 법적 고지 화면이 없으므로 GPLv3 §5(d) 의무가 생기지 않음).
6. **Windows 처리**:
   - 배포·공식 지원은 중단한다.
   - Windows를 대상으로 하는 코드는 유지하고, 자동 빌드·테스트도 계속 돌린다(검증되지 않는 보안 코드를 남기지 않기 위함).
   - Windows 코드 제거는 별도 후속 명세에서 다룬다.
7. **포크 Windows 빌드 사용자**:
   - 지원 종료(EOL)를 고지한다.
   - 원저작자 앱으로 옮기는 수동 절차를 문서로 제공한다(데이터 손실 범위 명시).
   - 데이터 내보내기 기능을 새로 만들지는 않는다.
8. **macOS·Linux 기존 사용자**: 첫 실행 때 1회성 마이그레이션을 제공한다. 자격증명은 새 식별자 기준으로 **이전**하며, 원저작자 앱과 서비스명을 공유하지 않는다. 모바일은 안내 문서로 대신한다.
9. **업스트림 보안 조율**: 포크가 찾은 결함 중 원저작자 최신 릴리스에도 남은 것은 공개 비교나 분리 공지 전에 원저작자에게 비공개로 알리거나 수정을 제안한다. 이는 "업스트림 병합 금지"의 예외로, 동기화가 아닌 기여에 해당한다.
10. **원저작자 사전 고지**: 분리 요청 전에 정중히 알린다. 이의가 있으면 따른다.
    - 이름 사용에 이의가 있으면 → 제품명을 변경한다.
    - Windows 사용자 안내에 이의가 있으면 → "이 포크는 Windows를 지원하지 않습니다"로만 표기한다.
11. **문서 언어**: 헌법대로 한국어로 작성한다. 포크 안내 배너에만 영문 한 줄을 병기한다.
12. **버전 구분**: 버전 번호만으로 포크를 구분하지 않는다.
    - 첫 독립 릴리스 버전은 게시 시점에 **원저작자가 이미 쓴 릴리스 버전과 겹치지 않아야** 한다.
    - 릴리스 제목과 산출물 이름에 포크 정체성이 드러나야 한다.

13. **제품 표시명**: 원저작자 앱과 구분되는 표시명·설치 이름을 쓴다. 이로써 macOS·Linux·Android에서 원저작자 앱과 같은 기기에 함께 설치할 수 있어야 한다. 구체적인 이름은 첫 독립 릴리스 전에 정하고, 원저작자 앱의 이름·설치 이름·패키지 이름과 겹치지 않는지 확인한 결과를 기록한다.
14. **Android의 지위**: 우선순위를 낮춘 **유지 플랫폼**으로 계속 배포한다. 중점 플랫폼(macOS·iOS·Linux)만큼의 검증·품질 투자는 약속하지 않지만, 릴리스 산출물·고정 서명 키·업데이트 연속성은 유지한다.
15. **iOS 배포 경로**: 공개 배포 채널(TestFlight·App Store) 확보는 후속 명세로 미룬다. 이번에는 지원 범위 원문에 iOS를 "소스 빌드로만 제공"한다고 실제 상태를 명시한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 라이선스 준수와 출처·저작권 귀속 (Priority: P1)

메인테이너로서, GPLv3 의무를 지키면서 원저작자와 포크 기여자의 저작권 귀속과 변경 사실을 정확히 밝히고, 모든 배포물이 같은 라이선스를 선언하길 원한다.

**Why this priority**: 저작권 귀속이나 변경 고지가 빠진 상태로 독립 릴리스를 배포하면 곧바로 카피레프트 의무 위반 위험이 생긴다. 다른 모든 작업의 전제다.

**Independent Test**: 라이선스 전문 무변경 여부, 귀속·변경 고지의 위치와 내용, 모든 패키지·설치 메타데이터의 라이선스 선언, 의존성 라이선스 자동 감사 결과를 점검해 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 원저작자 저작권 고지가 원래 어디에도 없는 상태에서, **When** 법적 고지 정비를 마치면, **Then** 원저작자 귀속 표기가 **새로 작성**되어 있고, 표기 주체·연도는 원저작자가 공개적으로 쓰는 표기를 따른다.
2. **Given** 포크 변경분의 저작권 표기를 작성할 때, **When** 권리 주체 근거를 확인하면, **Then** 근거가 있는 주체로 표기하고, 조직 명의를 쓸 근거가 없으면 기여자 개인을 표기한다.
3. **Given** 변경 고지를 작성할 때, **When** 고지 내용을 점검하면, **Then** 분기 기준(`v0.1.6`/`44c4d37`), 분리 일자, 주요 변경 요약이 모두 들어 있다.
4. **Given** 모든 배포물과 패키지·설치 메타데이터를, **When** 라이선스 선언을 비교하면, **Then** 모두 `GPL-3.0-only` 하나로 일치한다.
5. **Given** GPLv3와 호환되지 않거나 라이선스가 없는 의존성이 추가될 때, **When** 자동 감사가 실행되면, **Then** 감사가 실패한다.

### User Story 2 - 지원 범위 전환과 사용자 안내 (Priority: P1)

macOS·iOS·Linux 사용자는 이 포크가 자기 플랫폼을 지원한다는 것을 바로 알 수 있어야 한다. Windows 사용자는 혼동 없이 원저작자 앱으로 안내받아야 한다.

**Why this priority**: 분리 목적 그 자체다. 원저작자가 같은 이름의 앱을 배포하고 있으므로, 안내가 잘못되면 사용자 혼동과 원저작자에 대한 결례가 동시에 생긴다.

**Independent Test**: 공개 문서와 앱 내 정보 화면의 지원 범위 문구가 하나의 원문과 일치하는지, 원저작자 역할을 규정하는 표현이 없는지, 원저작자 링크가 유효한지, 이슈 등록 경로가 맞는지를 점검해 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** Windows 사용자가, **When** 저장소 첫 화면이나 릴리스 페이지를 열면, **Then** 이 포크가 Windows를 지원하지 않는다는 사실과 원저작자 앱 링크를 바로 볼 수 있다.
2. **Given** 지원 범위 문구가 하나의 원문으로 정의되어 있을 때, **When** 저장소 첫 화면·고지 문서·변경 이력·기여 가이드·이슈 등록 양식·앱 내 정보 화면·헌법을 확인하면, **Then** 7곳 모두에 같은 의미로 실려 있다.
3. **Given** 원저작자 앱과의 비교 정보를 게시할 때, **When** 내용을 검토하면, **Then** 검증 가능한 사실만 담겨 있고, 원저작자에게 아직 알리지 않은 보안 결함은 언급하지 않는다.
4. **Given** 사용자가 이슈를 등록할 때, **When** 플랫폼을 선택하면, **Then** 이 포크가 지원하는 플랫폼만 선택할 수 있고, Windows 사용자는 원저작자 저장소로 안내된다.

### User Story 3 - 저장소 분리와 분기 기준선 보존 (Priority: P2)

메인테이너로서, 저장소가 포크 네트워크에서 분리되어 PR이 자기 저장소를 기본 대상으로 삼고 코드 검색이 동작하며, 업스트림 동기화 경로가 어디에도 남지 않길 원한다.

**Why this priority**: 독립 운영의 실무 기반이지만, 법적 고지와 지원 범위 안내가 먼저 갖춰져야 원저작자에게 분리를 알리고 요청할 수 있다.

**Independent Test**: 저장소 포크 상태, 원격 저장소 설정, 기준선 태그, 자동화 안의 동기화 경로 유무를 점검해 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 분리 절차가 끝났을 때, **When** 저장소 상태를 확인하면, **Then** 독립 저장소로서 PR 기본 대상이 자기 `main`이고 코드 검색이 동작한다.
2. **Given** 분리 요청을 제출하기 전에, **When** 원격 저장소를 확인하면, **Then** 기준선 태그가 이미 게시되어 있고 분기 이후 업스트림 릴리스(작성 시점 `v0.2.0`·`v0.2.1`) 미병합 사실이 기록되어 있다.
3. **Given** 분리 요청을 제출하려 할 때, **When** 안전 게이트(FR-025)를 확인하면, **Then** 분리 단계 항목(1–5)을 모두 통과한 뒤에만 제출된다.
4. **Given** 분리 전후의 모든 작업에 대해, **When** 저장소 이력과 고지를 점검하면, **Then** 이력 재작성(강제 푸시 등)과 저작권·출처 고지 삭제는 일어나지 않았다. 일반적인 리팩터링에서 원저작자 유래 코드를 수정·삭제하는 것은 허용된다.

### User Story 4 - 포크 Windows 빌드 사용자의 지원 종료와 전환 (Priority: P2)

포크가 게시한 Windows 빌드(`0.1.6-alpha`·`0.1.6-beta`)를 쓰던 사용자로서, 지원이 끝났다는 사실과 원저작자 앱으로 안전하게 옮기는 방법, 그때 잃는 데이터를 미리 알고 싶다.

**Why this priority**: 배포를 중단하는 순간 기존 Windows 사용자가 고립되므로, 배포 중단과 같은 시점에 안내가 준비되어 있어야 한다.

**Independent Test**: 기존 Windows 릴리스의 지원 종료 고지, 전환 절차 문서, 실제 Windows 환경에서 절차를 수행한 기록을 점검해 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 기존 Windows 프리릴리스에 대해, **When** 사용자가 릴리스 페이지를 열면, **Then** 지원 종료 고지가 보이며, 이미 게시된 산출물은 삭제되지 않았다.
2. **Given** 포크 데이터 형식이 원저작자 앱과 호환되지 않는 상태에서, **When** 사용자가 전환 절차 문서를 읽으면, **Then** 비호환 사실과 함께 백업, 포크 앱 데이터 정리, 원저작자 앱 설치, 책 파일 다시 가져오기, 잃는 항목(읽기 진행률·책갈피·표시 설정·WebDAV 자격증명)을 안내받는다.
3. **Given** 전환 절차 문서가 준비되었을 때, **When** 실제 Windows 환경에서 원저작자 최신 앱으로 절차를 끝까지 수행하면, **Then** 한 번 이상 성공한 검증 기록이 남는다.
4. **Given** 포크 Windows 빌드 관련 이슈가 들어왔을 때, **When** 메인테이너가 처리하면, **Then** 포크 저장소에서 접수해 전환 안내로 종결하고, 포크 빌드 문제를 원저작자 저장소에 올리지 않도록 안내한다.

---

### User Story 5 - 앱 정체성 분리와 원저작자 앱과의 공존 (Priority: P3)

최종 사용자로서, 포크 앱이 원저작자 앱과 식별자·서명·설치 위치에서 충돌하지 않고, 앱 안의 모든 정보와 링크가 포크 프로젝트만 가리키길 원한다.

**Why this priority**: 같은 기기 충돌을 끝내는 근본 조치지만, 기존 사용자 데이터 보호(US6) 없이 단독 출시하면 데이터가 사라진 것처럼 보이므로 US6와 함께 출시한다.

**Independent Test**: 모든 플랫폼의 식별자 일치, 구 식별자 잔존 여부, 같은 기기 동시 설치 결과, 릴리스 산출물 메타데이터를 점검해 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 모든 플랫폼 설정·네이티브 프로젝트·검증 도구에 대해, **When** 식별자를 점검하면, **Then** 모두 새 식별자로 일치하고, 구 식별자 구조가 다시 생기면 자동 검사가 실패한다.
2. **Given** 원저작자 앱이 설치된 macOS·Linux·Android 기기에서, **When** 포크 앱을 설치하면, **Then** 두 앱이 서로 덮어쓰거나 설치가 실패하지 않고, 각 앱이 구분되는 이름으로 표시되며 자기 데이터만 쓴다.
3. **Given** 연속된 두 포크 Android 릴리스가 있을 때, **When** 이전 버전 위에 새 버전을 설치하면, **Then** 두 릴리스 모두 포크가 소유한 고정 서명 키로 서명되어 있어 업데이트 설치가 성공한다.

---

### User Story 6 - macOS·Linux·모바일 기존 사용자의 데이터 연속성 (Priority: P3)

구 식별자로 포크 앱을 쓰던 사용자로서, 새 식별자 버전으로 업데이트해도 서재·진행률·책갈피·설정·WebDAV 연결을 잃지 않길 원한다. 잃는 경우에는 그 사실과 복구 방법을 안내받고 싶다.

**Why this priority**: 식별자 변경(US5)의 부작용을 막는 필수 짝이며, US5와 같은 릴리스에 포함되어야 한다.

**Independent Test**: macOS·Linux에서 구 데이터를 가진 상태로 첫 실행 이전, 재실행 시 동작, 손상 데이터 처리, 자격증명 이전, 모바일 안내 문서를 점검해 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 구 위치에 데이터가 있고 새 위치가 비어 있을 때, **When** 새 식별자 버전을 처음 실행하면, **Then** 검증된 데이터만 1회 이전되고 원본은 보존된다.
2. **Given** 새 위치에 이미 데이터가 있을 때, **When** 앱을 실행하면, **Then** 아무것도 덮어쓰지 않는다.
3. **Given** 이전 도중 실패가 발생했을 때, **When** 앱이 계속 실행되면, **Then** 앱은 정상적으로 쓸 수 있고, 상황과 수동 복구 방법을 앱 안에서 안내한다.
4. **Given** 구 식별자 기준으로 저장된 자격증명이 있을 때, **When** 이전이 수행되면, **Then** 새 식별자 기준으로 옮겨지고, 평문으로 노출되거나 원저작자 앱과 공유되지 않는다.
5. **Given** 이전 대상 경로에 링크나 민감 경로가 섞여 있을 때, **When** 이전을 처리하면, **Then** 기존 신뢰 경계 규칙(경로 정규화, 민감 경로 차단, 링크를 통한 경계 이탈 차단)이 똑같이 적용된다.
6. **Given** iOS·Android 사용자가, **When** 업데이트 안내를 확인하면, **Then** 자동 이전이 안 된다는 사실과 대체 경로(WebDAV 동기화, 파일 다시 가져오기)를 안내받는다.

---

### User Story 7 - 거버넌스·기여 문서와 릴리스 파이프라인 전환 (Priority: P4)

기여자로서, 기여 가이드·보안 정책·변경 이력·헌법이 독립 포크의 운영 원칙을 일관되게 담고, 릴리스 자동화가 포크의 지원 범위만을 위해 동작하길 원한다.

**Why this priority**: 장기 운영의 기반이지만, 사용자에게 바로 드러나는 위험은 앞선 스토리보다 작다.

**Independent Test**: 각 문서의 필수 내용, 헌법 개정, 릴리스 산출물 구성과 체크섬, CI의 검증·라이선스 감사 실행 여부를 점검해 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 태그 릴리스가 실행될 때, **When** 산출물을 확인하면, **Then** 지원 플랫폼 산출물만 게시되고 Windows 설치 파일은 0개이며, 체크섬 목록이 함께 게시된다.
2. **Given** PR이 열리거나 `main`에 반영될 때, **When** 자동 검증이 실행되면, **Then** 전체 품질 검증과 라이선스 감사가 수행되고 Windows 대상 컴파일·테스트도 포함된다.
3. **Given** 헌법을 확인할 때, **When** 식별자·지원 플랫폼·독립 포크 원칙 조항을 읽으면, **Then** 모두 이 명세의 결정대로 개정되어 있다.

---

### Edge Cases

- 구 위치와 새 위치에 모두 데이터가 있을 때: 병합하지 않고 새 위치를 우선하며, 사용자에게 안내한다.
- 구 위치는 포크 구버전과 원저작자 앱이 함께 쓰던 곳이라, 그 안의 데이터가 어느 앱이 만든 것인지 구분할 수 없을 때: 원본은 건드리지 않고 복사만 하며, 이전 안내에 이 사실을 밝히고 사용자가 이전 결과를 버리고 빈 상태로 시작할 수 있게 한다.
- 이전 중 구 앱(포크 구버전 또는 원저작자 앱)이 실행 중이거나 포크 앱이 두 번 실행될 때: 데이터가 어긋나지 않도록 이전을 미루거나 한 번만 실행되게 하고, 사용자에게 안내한다.
- 사용자 지정 저장 폴더가 구 앱 데이터 폴더 안을 가리킬 때: 경로를 다시 연결한다.
- 자격증명 이전이 OS 정책 때문에 실패할 때: 재입력을 안내하고, 평문 저장은 하지 않는다.
- 포크 Windows 빌드 사용자가 백업 없이 원저작자 앱을 먼저 설치했을 때: 원저작자 앱이 서재를 열지 못하는 증상과 복구 절차를 안내한다.
- 원저작자가 이름 사용이나 Windows 안내에 이의를 제기할 때: 확정 결정 10번을 따른다.
- 원저작자가 앞으로 Windows 배포를 중단하거나 저장소를 보관 처리할 때: 안내 문구를 갱신한다.
- 원저작자가 포크와 같은 버전 번호로 릴리스할 때: FR-024를 따른다.
- 포크 네트워크 분리 요청이 지연·거절될 때: 임시 운영(PR 대상 수동 지정)과 대안(새 저장소로 미러링)을 둔다.
- 기여자 로컬에 업스트림 원격이 남아 있거나 포크 동기화 기능을 실수로 실행했을 때: 감지하고 되돌리는 절차를 둔다.
- Android 서명 키를 분실하거나 유출했을 때: 업데이트 경로가 끊기므로 사용자에게 고지하고 재설치를 안내한다.
- 비밀값이 없는 외부 PR 빌드: 서명을 뺀 검증은 계속 수행한다(FR-017).
- 의존성 갱신으로 새 라이선스가 생겨 감사가 실패할 때: 허용 여부를 검토해 허용 목록을 고치거나 의존성을 바꾼다. 검토 없이 감사를 우회하지 않는다.
- 원저작자에게 알린 보안 결함이 오랫동안 고쳐지지 않을 때: 공개 시점 기준을 미리 정해 둔다.
- 원저작자와의 비공개 연락 경로를 끝내 확보하지 못할 때: 정해 둔 기간이 지나면 결함 내용을 공개하지 않은 "통지 시도 기록"으로 보안 조율 단계를 대신하고, 원저작자 앱에 남은 결함에 관한 공개 문구는 계속 쓰지 않는다.
- Linux 배포판 차이(설치 패키지 형식, 디스플레이 서버, 웹 화면 엔진 버전): 중점 플랫폼 품질을 어디까지 보장할지 정해 지원 범위 원문에 반영한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (라이선스 전문 보존)**: 라이선스 전문을 바꾸지 않아야 한다(MUST).
- **FR-002 (귀속·변경 고지 작성)**: 원저작자 귀속 표기를 새로 작성하고, 포크 기여분의 저작권 표기(권리 주체 근거 확인 후)와 GPLv3 §5(a) 변경 사실·날짜 고지를 고지 문서·변경 이력·저장소 첫 화면에 기재해야 한다(MUST). 원래 없던 고지를 "보존된 원문"처럼 표현해서는 안 된다(MUST NOT).
- **FR-003 (라이선스 선언 일치)**: 모든 패키지·설치 메타데이터에 `GPL-3.0-only`를 선언해야 한다(MUST). 이 선택이 포크의 결정이라는 점과 재검토 조건을 고지 문서에 남긴다.
- **FR-004 (앱 내 정보 화면)**: 앱 이름·버전·라이선스·저장소 주소·원저작자 출처·변경 일자·지원 범위 문구·주요 서드파티 고지를 보여주는 정보 화면을 제공해야 한다(MUST). 이 화면은 자발적 정책이며, 법적 의무라고 표기해서는 안 된다(MUST NOT). 외부 링크는 이 포크 저장소와 원저작자 저장소만 허용하는 목록으로 제한하고(현재 앱에는 외부 링크 규칙이 없으므로 새로 정의한다), 접근성 규칙을 따른다.
- **FR-005 (서드파티 라이선스 호환 감사와 고지)**: 네이티브와 프론트엔드 런타임 의존성 모두에 대해, **직접·전이 의존성 전체**를 GPLv3 호환 허용 목록으로 자동 감사해야 한다(MUST). 허용 목록에는 실제로 쓰이는 라이선스만 둔다. 배포물에 포함되는 모든 서드파티 구성요소의 저작권 고지와 라이선스 전문을 배포물과 함께 제공해야 하며(MUST), 서드파티 고지 문서와 정보 화면은 실제 의존성과 일치해야 한다. 복수 라이선스 의존성은 선택한 라이선스를 기록해야 한다(MUST).
- **FR-006 (지원 범위 단일 원문)**: 지원 등급(중점: macOS·iOS·Linux / 유지(우선순위 낮음): Android / 비지원·원저작자 앱 권장: Windows / 개발 보조: 웹 폴백)과 iOS의 실제 제공 방식("소스 빌드로만 제공", 공개 배포 채널 없음)을 하나의 원문으로 정의해야 한다(MUST). 저장소 첫 화면·고지 문서·변경 이력·기여 가이드·이슈 등록 양식·정보 화면·헌법 7곳에 같은 의미로 실어야 한다(MUST).
- **FR-007 (표현 원칙)**: 공개 문구는 포크의 범위만 서술해야 한다(MUST). 원저작자 프로젝트의 역할·의도를 규정하거나 원저작자 앱을 낮추어 평가해서는 안 된다(MUST NOT). 원저작자 앱과의 비교 정보는 검증 가능한 사실만 담고, 원저작자에게 알리지 않은 보안 결함은 포함하지 않아야 한다(MUST NOT).
- **FR-008 (Windows 배포 중단, 검증 유지)**: 릴리스에서 Windows 산출물을 생성·게시하지 않아야 한다(MUST). Windows를 대상으로 하는 코드는 유지하되, CI에서 컴파일과 자동 테스트를 계속 수행해야 한다(MUST).
- **FR-009 (Windows 지원 종료 정책)**: 기존 Windows 프리릴리스에 지원 종료 고지를 추가하고(산출물은 삭제하지 않음), 포크 Windows 빌드 이슈를 처리하는 방침(포크 저장소에서 접수 → 전환 안내로 종결)을 문서화해야 한다(MUST).
- **FR-010 (Windows 전환 절차)**: 포크 데이터 형식이 원저작자 앱과 호환되지 않는다는 사실, 전환 절차, 손실 항목을 문서화하고, 실제 Windows 환경에서 원저작자 최신 앱으로 검증해야 한다(MUST). 호환된다고 단정하는 문구를 써서는 안 된다(MUST NOT).
- **FR-011 (저장소 분리)**: 포크 네트워크 분리를 요청하고, 로컬 원격 저장소 설정과 자동화에서 업스트림 동기화 경로를 없애며, 포크 동기화 기능을 쓰지 말라는 규칙을 기여 가이드에 명시해야 한다(MUST).

## Assumptions

- 원저작자는 앞으로도 Windows 앱을 배포·유지한다(근거: 2026-11-17 `v0.2.0`의 Windows 네트워크 폴더 수정). 이 가정이 깨지면 안내 문구를 갱신한다.
- 원저작자 앱은 `v0.2.1` 기준으로도 내부 데이터 형식 버전 1을 쓴다. 바뀌면 Windows 전환 절차를 다시 검증한다.

- Windows 배포 중단은 GPLv3 소스 제공 의무와 무관하다. 소스는 계속 공개되며, Windows에서 직접 빌드하는 것을 막지 않는다. 다만 지원하지 않는다.
- GitHub Support 요청, 원저작자 연락, 비밀값 등록, 서명 키 보관, 스토어 계정 작업은 메인테이너가 직접 수행한다. 명세는 절차와 검증 기준만 정의한다.
- 헌법 v3.3.0은 모든 플랫폼의 앱 식별자를 `com.edith.easyviewer`로 고정하고 Windows를 지원 플랫폼으로 명시해 이 명세와 충돌했다. 2026-11-17 헌법 v4.0.0 개정으로 식별자, 지원 플랫폼 등급, 독립 포크 운영 원칙(제8원칙)을 반영했다(FR-023의 헌법 항목).
- 확인된 기술 사실, 영향 범위, 리서치 항목, 작업 순서 제약은 입력 문서 §4에 있으며 `/speckit-plan`에서 참고한다.
