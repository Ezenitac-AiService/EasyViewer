# macOS 데이터 이전 실측 (T076, quickstart §3)

| 필드 | 내용 |
|---|---|
| 날짜 | 2026-11-18 |
| 환경 | macOS (Darwin 27.2), Apple Silicon. 새 앱: `npx tauri build --debug --bundles app`로 만든 `Pagelight.app`(`com.ezenitac.easyviewer`, 0.1.6-beta, ad-hoc 서명) |
| 구 데이터 | 이 Mac에 이미 있던 구 식별자 데이터. `~/Library/Application Support/com.edith.easyviewer`(책 2권: EPUB 1, TXT 1), `~/Library/WebKit/com.edith.easyviewer`(파일 18개, 읽기 진행률 포함). WebDAV 연결과 키체인 항목은 없음 |
| 실행 방법 | 앱 실행 파일(`Contents/MacOS/pagelight`)을 직접 실행하고 표준 출력을 기록. 결과는 새 식별자 폴더·`migration-v1.json`·해시로 관찰. 시나리오 2는 화면 캡처로도 확인 |
| 안전 조치 | 실행 전에 구 폴더 두 곳을 백업하고 SHA-256 목록을 만듦. 매 시나리오 뒤 원본 해시를 비교. 마지막에 테스트가 만든 새 식별자 폴더 3곳(Application Support·WebKit·Caches)을 지워 테스트 전 상태로 되돌림 |

## 시나리오별 결과

| # | 시나리오 | 관찰 | 판정 |
|---|---|---|---|
| 1 | 구 빌드로 데이터 준비(책 3권, WebDAV 연결 1개) | 구 빌드가 설치되어 있지 않아 새로 만들지 않고 기존 데이터(책 2권, WebDAV 없음)를 사용 | **BLOCKED**(WebDAV·키체인 데이터 없음) |
| 2 | 새 빌드 첫 실행 | `state: migrated`, `copied.dataDir`·`webviewStore` 모두 `true`. 화면 캡처에서 메인 창에 책 2권과 읽기 진행률("3장. 윤동주 시선 - 별 헤는 밤")이 그대로 보이고 이전 안내 대화상자("이전 버전 데이터를 옮겼습니다", [이전 결과 버리기]/[확인])가 표시됨. 서재 기록의 책 경로가 구 경로 2건 → 새 경로 2건으로 다시 연결됨(IndexedDB 사본 문자열 검사). 구 폴더 해시 불변 | **PASS**(WebDAV 자격증명 부분은 데이터가 없어 확인 못 함) |
| 3 | 새 앱 재실행 | 새 앱 데이터 폴더(기록·`books/`) 해시가 재실행 전후 동일. 책 파일 2개, 서재 경로 참조 2건 그대로(중복 없음) | **PASS** |
| 4 | 구 폴더에 외부 폴더를 가리키는 심볼릭 링크와 0바이트 EPUB 추가 | `skippedEntries: 1`, 링크는 복사되지 않음. 앱 크래시 없음, 재구성까지 진행(`reconstructed: true`). 0바이트 EPUB은 서재에 등록되지 않음(경로 참조 0건). 테스트 파일을 지운 뒤 구 폴더 해시가 원본과 같음을 확인 | **PASS**. 손상 파일 안내는 이 실측 뒤 보완함(아래 "발견" 1) |
| 5 | 새 폴더 쓰기 권한 제거(두 대상 모두 `555`로 미리 생성) | 앱 데이터는 복사됨(빈 폴더는 상위 폴더 권한으로 교체되므로), WebKit 저장소는 실패 → `state: partial`, `error: permission`. 앱 크래시 없음, 재구성 실행. 안내 화면은 화면 캡처가 검게 찍혀 눈으로 확인하지 못함 | **PASS**(기록·생존), 안내 표시는 **BLOCKED** |
| 6 | 구 앱 실행 중 새 앱 실행 | 구 식별자 앱이 설치되어 있지 않고, 네이티브 대화상자 버튼을 누를 화면 제어 도구가 이 세션에 없음 | **BLOCKED** |
| 7 | 새 앱을 거의 동시에 두 번 실행 | 4초·14초 시점 모두 프로세스 1개. `state: migrated` 1회, 임시 `.migrating` 폴더 없음, 책 2권(중복 없음) | **PASS** |
| 8 | WebDAV 연결 2개로 자격증명 이전 건너뛰기 | WebDAV·키체인 데이터 없음, 클릭 도구 없음 | **BLOCKED** |
| 9 | 이전 결과 버리기 | 버튼 클릭 대신 기록을 `discard_pending`으로 바꾸고 재시작(버튼이 하는 일과 같음). 창 생성 전에 이전한 데이터가 비워지고 `state: discarded`. 새 WebKit 저장소가 다른 해시 폴더로 새로 만들어지고 빈 서재에 샘플 도서가 새로 들어감(파일 시각 16:59, 크기 6392 ≠ 원본 6416). 다시 실행해도 `discarded` 유지. 구 폴더 해시 불변 | **PASS**(핵심 동작), 버튼 클릭·재시작 경로는 단위 테스트로만 확인 |

- 진행 창: 이 Mac의 데이터가 작아 복사가 5초 안에 끝나 진행 창은 뜨지 않았다(정상). 큰 서재로 확인하지 않았다.
- 구 폴더 원본은 모든 시나리오 뒤 SHA-256 목록이 처음과 같았다(US6-1).

## 발견

1. **손상 파일 안내 없음 → 보완함(2026-11-18)**: 재구성(`reconstructLibrary`)이 읽거나 등록하지 못한 파일을 이미 있는 파일과 같은 `skipped`로 세어 조용히 넘어갔다. 결과에 `failed`를 따로 두고, 안내에 "책 파일 N개는 손상되었거나 읽을 수 없어 서재에 넣지 못했습니다. 원본 파일을 [책 추가]로 다시 가져오세요."를 표시하도록 고쳤다. 주 안내를 이미 닫았어도 이 내용은 표시한다. 단위 테스트(`libraryReconstruction.spec.ts`, `migrationNotice.spec.ts`)로 확인했고, 실기기 화면 표시는 화면 제어가 가능한 환경에서 시나리오 4를 다시 실행해 확인해야 한다.
2. **화면 캡처 권한**: `screencapture`가 macOS 화면 기록 권한 요청 창을 띄웠고, 이후 캡처는 검게 찍혔다. 안내 화면의 시각 검증은 화면 제어가 가능한 환경에서 다시 해야 한다.

## 남은 확인

- 시나리오 1·6·8: 구 식별자 빌드 설치, WebDAV 연결과 키체인 항목, 대화상자 클릭이 필요하다(S2 스파이크와 함께).
- 시나리오 5의 안내 화면, 시나리오 9의 버튼 클릭 경로, 큰 서재에서의 진행 창.
