## Clarifications

### Session 2026-11-16

- Q: 기존 도서 식별자를 전체 콘텐츠 지문 기반으로 전환할 때 하위 호환성과 미보완 도서 재등록 중복을 어떻게 처리할까요? (`FR-006`) → A: 기존 도서 ID는 유지하고 별도 `콘텐츠 지문` 필드를 도입한다. 신규 가져오기 시 파일 크기가 일치하는 미보완 기존 도서만 즉시 온디맨드 해싱해 연결하고, 나머지는 열람·유휴 시 점진 보완한다.
- Q: 보안 중계 프록시가 없는 정적 웹 환경에서 원격 다운로드 및 인증 포함 요청을 어떻게 제어할까요? (`FR-003`) → A: 고위험 내부망(IPv6 전환 대역 포함)과 평문(`HTTP`) 인증 요청은 동의 여부와 무관하게 항상 차단하고, 암호화(`HTTPS`) 인증 요청만 위험 고지 및 명시적 사용자 동의 후 현재 실행 세션 메모리 자격증명으로 예외 허용한다(영구 저장 금지).
- Q: 대용량 전자책 열람 시 위치 색인 생성과 화면 렌더링 순서를 어떻게 조율할까요? (`FR-008`, `SC-003`) → A: 첫 페이지 화면 표시를 완료한 직후에만 백그라운드 색인을 시작하며(지문 유무와 무관하게 첫 화면 동기 대기 금지), 색인 중에는 섹션 비중 근사 탐색을 제공하고 완료 시 지문별로 로컬 캐시한다.
- Q: 데스크톱 외부 저장 폴더 쓰기 실패 및 조기 화면 이탈 시 데이터 유실을 어떻게 방지할까요? (`FR-004`, `FR-005`) → A: 쓰기 실패 시 침묵 폴백 없이 중단 후 인앱 복구 선택지를 제공하고, 화면 이탈·종료 시 대기 중인 독서 위치와 도서 메타데이터의 최근 열람 시각을 함께 즉시 확정 저장한다.
- Q: 전자책 콘텐츠 정화(`FR-002`), 네이티브 대용량 수신(`FR-007`), 모듈 규모 상한(`FR-011`), 플랫폼 식별자·프리릴리즈 패키징(`FR-014`) 기준은? → A: 구조 파서 및 명시적 안전 스킴 허용 목록(`FR-002`), 백엔드 고정 버퍼 스트리밍·전 구간 데드라인·EPUB 2/3 표지 호환 추출(`FR-007`), 프로덕션 모듈 450줄 이하 정적 게이트(`FR-011`), 전 플랫폼 `com.edith.easyviewer` 통일·레거시 패키지 경로 차단·일관된 프리릴리즈 번들 분기(`FR-014`)를 적용한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 다중 OS 신뢰 경계 및 콘텐츠·경로 보안 빈틈 차단 (Priority: P1)

사용자 및 보안 감사자는 애플리케이션이 모든 지원 운영체제와 실행 환경에서 파일 시스템 경로 접근, 전자책 내장 콘텐츠 정화, 원격 네트워크 통신 검증을 예외나 편차 없이 동일하게 강제할 것을 기대한다. 공격적인 관점에서 특정 운영체제 고유 경로 표기(예: 확장 길이 경로 접두사, 운영체제별 시스템 디렉토리), 전자책 내장 스타일·속성 난독화 우회, 또는 비인가 로컬 파일 읽기 경로를 통한 우회 시도가 모두 단일 신뢰 경계에서 차단되어야 한다.

**Why this priority**: 1차 보안 리팩토링 이후에도 운영체제별 경로 정규화 편차, 로컬 파일 읽기의 이중 경로, 전자책 스타일·속성 정화의 난독화 벡터 등 실제 침해로 이어질 수 있는 잔여 우회 표면이 존재하므로 최우선으로 종결해야 한다.

**Independent Test**: 운영체제별 시스템·확장 경로 변형 입력, 난독화된 전자책 콘텐츠 샘플, 미승인 로컬 파일 경로, 비신뢰 원격 호스트 요청을 독립 검증 스위트에 입력해 모든 정상 요청은 허용되고 모든 악성·우회 벡터는 예외 없이 차단됨을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 데스크톱 및 모바일 애플리케이션에서 사용자가 승인된 저장 폴더 외부 또는 운영체제 보호 디렉토리(대소문자 혼합, 확장 경로 접두사, 심볼릭 링크 변형 포함)의 파일 읽기를 시도할 때, **When** 신뢰 경계가 경로를 정규화하고 화이트리스트를 검사하면, **Then** 플랫폼에 관계없이 모든 로컬 도서 읽기가 단일 신뢰 경계로 일원화되어 보호 경로·미승인 경로 접근을 100% 차단한다.
2. **Given** 난독화된 스타일 인코딩·주석·반응형 이미지 속성·비표준 미디어 링크 등 우회 패턴이 삽입된 전자책 문서가 열릴 때, **When** 콘텐츠 정화 및 격리 정책이 적용되면, **Then** 정상 본문과 내부 스타일은 유지되면서 외부 데이터 유출 경로와 능동 스크립트 실행 가능 벡터가 모두 제거된다.
3. **Given** 정적 웹 호스팅 등 네트워크 중계 프록시가 부재한 환경에서 사용자가 원격 도서·WebDAV 동기화 엔드포인트를 입력할 때, **When** 네트워크 보안 계층이 요청 가능 여부를 판정하면, **Then** 고위험 내부망과 평문(`HTTP`) 인증 요청은 동의 여부와 무관하게 무조건 거부하고, 비인증 공개 URL은 브라우저 출처 공유(CORS) 범위 내 허용하며, 암호화(`HTTPS`) 인증 요청은 기본적으로 차단·안내한 뒤 사용자가 보안 위험과 CORS 제약을 확인하고 명시적으로 동의한 경우에만 현재 실행 세션 메모리 내 자격증명으로 직접 연결을 허용한다(브라우저 영구 저장 금지).

### User Story 2 - 대규모 서재·대용량 도서 성능, 메모리 효율 및 데이터 유실 방지 (Priority: P1)

다수의 도서(수백 권 이상)와 대용량 전자책·원격 도서(수십~수백 MB)를 사용하는 독자는 앱 초기 기동 지연 없이 즉시 서재 화면을 보고, 도서 열람과 페이지 넘김 시 멈춤 현상이나 메모리 폭증 없이 쾌적하게 읽을 수 있어야 한다. 또한 독서 중 앱을 급하게 종료하거나 기기를 전환하더라도 마지막 읽은 위치, 책 식별성, 로컬 저장 데이터 및 표지 이미지가 손실되거나 손상되지 않아야 한다.

**Why this priority**: 현재 서재 목록과 표지 이미지를 매 페이지 전환마다 함께 직렬화·중복 저장하는 구조, 대용량 원격 파일 전송 시 수배에 달하는 메모리 급증, 첫 화면 렌더링 전 전체 위치 인덱싱 대기, 조기 종료 시 대기 중인 위치 저장 손실은 실사용 환경에서 체감 속도 저하와 데이터 유실·크래시를 유발하는 핵심 병목이다.

**Independent Test**: 수백 권 규모 서재 데이터와 대용량 전자책/텍스트 픽스처를 대상으로 초기 구동, 연속 페이지 전환, 표지 렌더링, 대용량 원격 수신, 열람 중 즉시 화면 이탈 시나리오를 실행해 메모리 상한 준수, 첫 화면 표시 지연 단축, 0건의 위치·데이터 유실을 독립 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 표지 이미지가 포함된 다수의 전자책이 등록된 서재에서 사용자가 독서를 진행하며 빠르게 페이지를 넘길 때, **When** 독서 위치가 갱신되고 저장되면, **Then** 표지 이미지 바이너리와 도서 메타데이터·독서 위치 저장소가 분리되어 전체 표지 데이터가 매번 재직렬화되지 않고, 제한된 동기 저장 영역의 용량 초과 오류가 발생하지 않는다.
2. **Given** 사용자가 대용량 원격 도서를 내려받거나 서재 초기화·열람을 시작할 때, **When** 초기 화면이 렌더링되고 파일이 전송되면, **Then** 뷰어 전용 무거운 기능은 필요 시점에 지연 로드되어 서재 첫 화면이 경량으로 기동되고, 원격 파일 수신 시 중복 문자열 변환 없는 이진 스트림 전송으로 메모리 급증이 억제되며, 전자책 열람 시 전체 위치 색인 완성 전에도 첫 페이지가 즉시 표시된다.
3. **Given** 파일 내용은 다르지만 앞부분 헤더와 크기가 유사한 여러 권의 도서를 가져오거나 사용자가 파일명을 변경해 재등록할 때, **When** 도서 고유 식별자를 생성하고 저장하면, **Then** 전체 콘텐츠 해시 기반 식별을 통해 서로 다른 도서가 덮어써지지 않으며, 저장 실패 시 침묵 폴백 대신 사용자에게 명확한 실패 원인을 알린다.
4. **Given** 독자가 페이지를 넘긴 직후 1초 이내에 뒤로 가기를 누르거나 화면을 닫을 때, **When** 열람 세션이 종료되면, **Then** 대기 중인 위치 저장 지연 작업이 즉시 확정 저장되어 마지막 읽은 위치가 누락 없이 보존된다.

### User Story 3 - 완전한 키보드·스크린리더 접근성, 상태 경합 차단 및 회복 탄력성 확보 (Priority: P2)

키보드나 스크린리더 등 보조 기술을 사용하는 사용자, 또는 모바일·데스크톱 환경에서 여러 작업을 빠르게 전환하는 사용자는 모든 모달 대화상자와 탐색 서랍에서 키보드만으로 초점 이탈 없이 조작할 수 있어야 하며, 도서 전환·조기 취소·네트워크 지연 상황에서도 UI 멈춤이나 이전 도서 데이터가 섞이는 경합 오류를 겪지 않아야 한다.

**Why this priority**: 현재 모달과 서랍 UI에 시맨틱 대화상자 속성과 포커스 트랩이 부재하고, 웹 환경 삭제 확인이 테마와 무관한 브라우저 기본 경고창에 의존하며, 열람 중 빠른 이탈·도서 전환·대량 가져오기 시 비동기 취소 및 로딩 상태 표시가 빠져 있어 사용성과 접근성 결함이 크다.

**Independent Test**: 모든 모달·서랍을 키보드(`Tab`, `Shift+Tab`, `Escape`)와 보조 기술 탐색만으로 개폐·조작해 초점 가두기 및 복귀를 확인하고, 열람 도중 급격한 취소/전환 및 중복 파일 가져오기 시 레이스 컨디션 없이 최신 상태만 유지됨을 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 서재의 다운로드·동기화·삭제 확인 모달이나 뷰어의 설정·목차 서랍을 키보드 또는 보조 기술로 열었을 때, **When** 대화상자 내부에서 탐색하고 닫기를 실행하면, **Then** 배경 요소로 초점이 새어나가지 않고(`Tab`/`Shift+Tab` 순환), `Escape` 키로 닫히며, 닫힌 직후 원래 열었던 버튼으로 초점이 정확히 복귀하고, 웹 삭제 확인 역시 앱 테마와 일관된 인앱 확인 대화상자로 동작한다.
2. **Given** 대용량 전자책 로딩 또는 네트워크 요청이 진행 중일 때, **When** 사용자가 서재로 복귀하거나 다른 도서로 즉시 전환하면, **Then** 이전 비동기 작업과 타이머가 즉시 취소·정리되어 이전 도서의 위치·목차·오류 상태가 새 화면이나 서재 상태를 오염시키지 않는다.
3. **Given** 사용자가 서재에서 여러 도서 파일을 한 번에 가져오거나 드롭할 때, **When** 파일 검증과 메타데이터 추출이 진행되면, **Then** 처리 중 상태와 진행 피드백이 명확히 표시되어 중복 가져오기·무응답 오인을 방지한다.

### User Story 4 - 거대 단일 모듈 분해 및 계층·도메인 응집도 재구성 (Priority: P3)

유지보수자와 신규 기여자는 1,000줄이 넘는 거대 단일 화면·모달·엔진·백엔드 모듈을 열람·수정할 때 화면 상태, 비동기 오케스트레이션, 순수 계산 로직, 보안 정책이 한 파일에 얽혀 변경 영향 범위를 예측하기 어려운 상태를 해소하고자 한다. 각 모듈이 단일 책임을 갖는 소규모 응집 단위로 분리되어야 기능 수정과 오류 추적이 독립적으로 가능해진다.

**Why this priority**: 거대 단일 모듈 구조가 그대로 유지되면 신규 기능 추가나 결함 수정 시 의도치 않은 부작용이 빈번하고, 화면 컴포넌트가 저장소 계층을 직접 호출하는 등 계층 일관성이 다시 무너질 위험이 높기 때문이다.

**Independent Test**: 리팩토링 후 정적 모듈 경계·복잡도 점검을 실행해 거대 단일 파일 해체, 화면 계층의 저장소 직접 호출 제거, 중복 유틸리티(예: 알림 토스트 타이머, 3중 네트워크 주소 분류 규칙)의 단일화, 전자책 엔진 교체 가능한 포트 추상화를 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 장문의 뷰어 화면, 원격 탐색기 모달, 전자책 엔진, 네이티브 신뢰 경계 모듈이 각각 책임별 하위 단위(화면 상태 조율, 원격 탐색기 뷰, 콘텐츠 정화, 위치 계산, 경로·네트워크 보안)로 분리되었을 때, **When** 유지보수자가 특정 영역(예: 책갈피, 원격 폴더 탐색, 경로 검증)을 수정하면, **Then** 관련 없는 렌더링·UI·네트워크 코드에 영향을 주지 않고 해당 단위만 수정 및 단위 검증할 수 있다.
2. **Given** 뷰어 화면이 도서 원본 바이너리를 불러오거나 알림 메시지를 띄울 때, **When** 상위 화면 코드를 점검하면, **Then** 하위 저장소 어댑터를 직접 호출하지 않고 도메인 스토어/서비스 경유 계약을 사용하며, 중복 구현된 토스트 타이머 관리가 단일 공용 메커니즘으로 통합되어 있다.
3. **Given** 향후 전자책 렌더링 라이브러리를 교체하거나 확장해야 할 때, **When** 상위 뷰어 조율 계층을 확인하면, **Then** 특정 서드파티 렌더링 라이브러리 내부 구조나 타입에 직접 결합되지 않고 추상화된 문서 뷰어 포트 인터페이스를 통해서만 통신한다.

### User Story 5 - 테스트 사각지대 해소 및 저장소·멀티 플랫폼 산출물 정합화 (Priority: P3)

유지보수자는 가장 크고 변경이 잦은 핵심 화면·모달·페이지 측정 엔진에 대한 자동 단위 검증 공백을 없애고, 소스 저장소에 불필요하게 추적되는 대용량 바이너리 및 플랫폼별 앱 식별자·버전 불일치를 정리해 전 플랫폼 배포 품질을 일관되게 유지하고자 한다.

**Why this priority**: 정적 게이트와 E2E 스모크 테스트가 통과하더라도, 가장 복잡한 핵심 컴포넌트·레이아웃 측정기·크로스 OS 보안 경로의 단위 테스트 공백과 저장소 내 플랫폼 설정 불일치는 장기적 회귀 위험을 남기기 때문이다.

**Independent Test**: 자동 검증 스위트를 실행해 기존 누락 영역(대형 뷰어/탐색기/페이지 측정 로직, 접근성 포커스·키보드 제어, 비동기 취소 경합, 표지 분리 저장, 크로스 OS 경로 보안 벡터)이 모두 단위/통합 테스트로 검증되고, 저장소의 대형 바이너리 추적 제거 및 다중 플랫폼 식별자 일치가 확인됨을 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 기존에 단위 테스트가 부재했던 대형 뷰어 흐름, 원격 탐색/인증 흐름, 실제 레이아웃 페이지 측정 계산기, 접근성 모달 동작에 대해, **When** 자동 검증 스위트를 실행하면, **Then** 외부 네트워크나 실제 OS 없이도 정상 흐름, 취소 경합, 접근성 키보드 순환 및 오류 복구 시나리오가 결정적으로 검증된다.
2. **Given** 소스 저장소와 다중 플랫폼 앱 설정을 점검할 때, **When** 저장소 추적 대상과 플랫폼 메타데이터를 확인하면, **Then** 소스 저장소 내에 배포용 대용량 설치 바이너리가 중복 추적되지 않고 릴리즈 배포 채널로 일원화되며, 모든 지원 플랫폼 설정의 앱 식별자와 버전 메타데이터가 단일 기준과 일치한다.

---

### Edge Cases

- 기존 버전 업그레이드 시 대량 표지 포함 서재 데이터의 무손실 분리 이관(`FR-004`), 0.5초 이내 급격한 페이지 이동 직후 화면 이탈 시 위치 및 최근 열람 시각 보존(`FR-004`, `FR-005`), 외부 폴더 쓰기 실패 시 비폴백 복구(`FR-005`)가 보장되어야 한다.
- 대용량 전자책 첫 페이지 렌더링 직후 백그라운드 색인 개시 및 중도 이탈 시 즉시 취소(`FR-008`, `FR-010`), 중첩 대화상자 열림 시 최상위 모달 단독 키보드 처리 및 비가시 요소 포커스 배제(`FR-009`)가 보장되어야 한다.
- 주석·이스케이프·조건부 규칙(`@media`/`@supports`/`@container`)이 결합된 스타일 및 외부 리소스 URI 차단(`FR-002`), 대소문자·확장 경로·네트워크 공유 경로 변형 차단(`FR-001`), IPv6 전환 대역(NAT64·6to4·Teredo·IPv4 호환 주소) 우회 및 저속 스트리밍 지연 공격 차단(`FR-003`, `FR-007`)이 보장되어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (단일 로컬 신뢰 경계 및 크로스 OS 경로 방어)**: 데스크톱과 모바일 애플리케이션의 모든 승인된 로컬 도서 파일 읽기·해싱·가져오기는 단일화된 신뢰 경계를 통과해야 하며(MUST), 경로 정규화 검사 시 모든 대상 운영체제의 시스템 보호 경로, 사용자 자격증명 저장소, 확장 길이 경로 접두사, 네트워크 공유 경로 및 심볼릭 링크 탈출 시도를 일관되게 거부해야 한다(MUST).
- **FR-002 (구조 파서 및 명시적 허용 목록 기반 도서 콘텐츠 정화)**: 전자책 내장 콘텐츠 정화 계층은 우회 가능한 정규식 기반 스타일 치환에 의존해서는 안 되며(MUST NOT), CSS·DOM 구조 구문 분석기와 명시적 안전 스킴·속성 허용 목록(내부 상대 경로, 로컬 블롭, 안전한 래스터 데이터 이미지 외 외부 `http:`/`https:` 및 능동 스킴 기본 거부)을 기반으로 동작해야 한다(MUST). 이를 통해 능동 태그·이벤트 속성, 모든 미디어·이미지·폼·소스 목록·배경 URI 속성의 외부 호출, 조건부 규칙을 포함한 스타일 내 이스케이프·주석 난독화, SVG/XHTML 네임스페이스 혼동 벡터를 구조적으로 차단하면서도(MUST), 정상적인 본문 조판 서식과 읽기 상호작용은 보존해야 한다(MUST).
- **FR-003 (네트워크 보안 규칙 동기화, IPv6 전환 대역 차단 및 비프록시 동의 정책)**: URL/IP 주소 분류 및 사설망·고위험 주소 차단 규칙은 클라이언트와 백엔드 전 구간에서 동일한 판정 결과를 보장하도록 동기화되어야 하며(MUST), 루프백·메타데이터·링크로컬뿐 아니라 내부 IPv4를 캡슐화하는 IPv6 전환 대역(NAT64, 6to4, Teredo, 구형 IPv4 호환 주소 등)까지 추출·차단해야 한다(MUST). 보안 프록시가 없는 정적 웹 환경에서 비인증 공개 URL 다운로드는 브라우저 보안(CORS) 범위 내 허용하되, 인증 헤더가 필요한 원격 요청은 기본적으로 차단하고 위험 고지 후 암호화 출처(`HTTPS`)에 대해 사용자가 명시적으로 동의한 경우에만 현재 실행 세션 메모리 한정 자격증명으로 직접 요청을 허용해야 하며(MUST), 평문(`HTTP`) 인증 요청과 브라우저 영구 비밀번호 저장은 항상 거부해야 한다(MUST).
- **FR-004 (표지·메타데이터·독서 위치 저장소 분리 및 열람 시각 정합성)**: 서재 도서 목록 메타데이터, 대용량 표지 이미지 바이너리, 독서 위치 기록은 독립적인 저장 단위로 분리되어야 하며(MUST), 페이지 전환 시마다 전체 도서 목록이나 표지 데이터가 재직렬화되거나 제한된 동기 캐시 용량을 소진해서는 안 된다(MUST NOT). 단, 독서 위치가 확정 저장(Flush)될 때에는 도서 메타데이터의 최근 열람 시각 및 마지막 위치 포인터도 경량 메타데이터 저장소에 함께 반영되어 앱 재시작 후에도 최근 읽은 순서 정렬이 유실되지 않아야 하며(MUST), 기존 버전 사용자의 메타데이터와 표지 이미지는 손실 없이 자동 이관되어야 한다(MUST).
- **FR-005 (독서 위치 확정 저장 및 쓰기 실패 복구 UI)**: 지연 병합(Debounce) 중인 독서 위치 및 열람 시각 저장 작업은 화면 이탈·문서 전환·애플리케이션 종료 시점 이전에 반드시 즉시 확정 저장(Flush)되어야 한다(MUST). 또한 데스크톱 지정 저장 폴더에 파일 쓰기가 실패할 경우 내부 저장소로 침묵 폴백하지 않고(MUST NOT) 도서 추가를 중단한 뒤 실패 사유와 함께 기본 앱 저장 폴더로 전환 후 재저장하거나 다른 폴더를 선택할 수 있는 인앱 복구 선택지를 제공해야 한다(MUST).
- **FR-006 (충돌 방지 콘텐츠 기반 도서 식별 및 하위 호환 유지)**: 도서 중복 판별 및 신규 도서 식별은 일부 바이트 샘플이나 파일명에만 의존하지 않고 전체 콘텐츠 지문 기반으로 수행되어 서로 다른 내용의 도서가 충돌·덮어쓰기 되지 않아야 하며(MUST), 이미 등록된 기존 도서는 기존 식별자를 유지해 독서 위치·책갈피·기기 간 동기화 스냅샷 호환성을 보존하고 열람 시점(필요 시 유휴 시간 병행)에 전체 콘텐츠 지문을 점진 보완해야 한다(MUST). 또한 파일명 변경 후 동일 콘텐츠를 재등록할 때 파일 크기가 일치하는 미보완 기존 도서 후보만 온디맨드 지문 계산으로 대조·연결해 중복 등록을 방지하고 기존 독서 위치·책갈피와의 연결 무결성을 유지해야 한다(MUST).

## Assumptions

- **기존 리팩토링(`001`) 자산 계승**: 1차 리팩토링에서 구축된 플랫폼 추상화 계층(`FR-004`/`FR-005` 구조), Zero-Trust 프록시/네이티브 원격 검증, 2계층 테스트 및 품질 게이트 체계를 유지하면서 발견된 구조적·성능적·보안적 잔여 결함과 기술 부채를 심층 해소한다.
- **전자책 렌더링 엔진 전략**: 본 리팩토링에서는 기존 전자책 렌더링 핵심 라이브러리를 즉시 전면 교체하기보다 먼저 **추상화 포트 뒤로 격리(`FR-012`)**하고 비차단 로딩(`FR-008`) 및 강화된 정화(`FR-002`)를 적용하는 것을 기본 가정으로 하며, 추후 포트를 유지한 채 차세대 경량 렌더러로 무중단 교체할 수 있는 기반을 마련한다.
- **하위 호환 마이그레이션 원칙**: 기존 사용자가 보유한 도서 메타데이터, 독서 위치, 책갈피, 원격 저장소 연결 기록 및 표지 이미지는 앱 최초 실행 또는 접근 시 비파괴적으로 자동 이관하여 어떠한 사용자 데이터도 손실되지 않도록 한다.
- **지원 플랫폼 일관성**: 모든 UI 접근성 및 인앱 대화상자 개선은 `light`·`dark`·`sepia` 3가지 테마와 데스크톱·모바일 뷰포트 모두에서 일관되게 동작하는 것을 기본 전제로 한다.
